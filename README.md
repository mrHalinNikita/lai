# LAI Estimator для Odoo 17

`lai_estimator` - это модуль Odoo 17 для оценки индекса листовой поверхности (`LAI`, Leaf Area Index) по загруженному пользователем RGB-изображению.

Модуль предназначен для практической работы, когда нужно:

- быстро получить оценку `LAI` по фотографии участка,
- построить карту растительности и карту распределения локального `LAI`,
- видеть не только итоговое число, но и понятные промежуточные метрики,
- выполнять анализ прямо внутри Odoo через веб-интерфейс.

## Назначение модуля

Пользователь загружает изображение через веб-форму, выбирает тип культуры или сцены и режим сегментации.

После этого модуль:

1. нормализует изображение,
2. при необходимости определяет рабочую область,
3. выделяет растительность,
4. оценивает покрытие и долю просветов,
5. вычисляет глобальный `LAI`,
6. строит карты визуализации,
7. сохраняет результат в Odoo.

На странице результата показываются:

- исходное нормализованное изображение,
- карта растительности,
- сводная тепловая карта,
- карта распределения локального `LAI`,
- оценка уверенности,
- метрики качества и интерпретации результата.

## Для чего используется модуль

Модуль полезен в таких задачах, как:

- полевой скрининг,
- сравнение состояния посевов по датам,
- быстрая оценка плотности растительного покрова,
- оценка вертикального озеленения,
- простой мониторинг листовой массы внутри ERP-процесса.

Типовые сценарии использования:

- агроном загружает серию фотографий одного и того же участка и сравнивает динамику `LAI`,
- оператор проверяет, становится ли покров плотнее или реже,
- пользователь хочет видеть карту распределения растительности, а не только одно итоговое число,
- технический специалист внедряет лёгкий веб-процесс оценки `LAI` прямо в Odoo.

## Основная идея расчёта

Модуль использует оптический подход на основе видимого покрытия растительностью и доли видимых просветов.

Базовая формула для глобального расчёта:

```text
LAI = -ln(gap_fraction) / k_eff
```

Где:

- `gap_fraction` — доля видимых просветов в сцене,
- `k_eff` — эффективный коэффициент ослабления, скорректированный под тип сцены и структуру покрова.

Это приближённая оценка, основанная на инверсии по Beer-Lambert, адаптированной для RGB-изображений и сегментации растительности.

## Общий конвейер обработки

### 1. Загрузка и нормализация изображения

Загруженное изображение:

- проверяется по размеру и формату,
- переводится в RGB,
- уменьшается до практического рабочего размера,
- нормализуется по цвету,
- слегка сглаживается для подавления шума.

Это снижает нагрузку на память и делает последующие этапы стабильнее.

### 2. Определение рабочей области

Если на изображении есть выделенная рамкой рабочая зона, модуль пытается определить её автоматически и анализировать только внутреннюю часть.

Это удобно, когда пользователь снимает выделенный квадрат учёта или специальную область наблюдения.

Если надёжно определить такую область не удалось, используется всё изображение.

### 3. Сегментация растительности

В модуле есть два режима сегментации:

- `cv_ensemble`
- `sam`

#### `cv_ensemble`

Это основной и рекомендуемый режим для рабочей эксплуатации.

Он использует набор RGB-индексов растительности и адаптивную логику порогов. Цель — получить устойчивую маску растительности при умеренном потреблении памяти.

Сегментация опирается на:

- `ExG`,
- `ExGR`,
- `NDI`,
- `VARI`,
- `GLI`,
- `CIVE`,
- близость оттенка к зелёному,
- насыщенность,
- доминирование зелёного канала,
- морфологическую очистку.

Этот путь быстрый, воспроизводимый и безопаснее для серверной памяти Odoo.

#### `sam`

Это экспериментальный режим на базе Segment Anything.

Чтобы избежать сильного расхождения карт между методами, `SAM` сначала использует тот же цветовой prior, что и `cv_ensemble`:

- строится support-mask на основе RGB-логики растительности,
- из этой области формируется prompt-box,
- `SAM` уточняет маску,
- итоговая маска объединяется с тем же support-mask.

Это важно, потому что оба метода должны быть близки друг к другу по выделяемым областям. Они могут отличаться в деталях, но не должны уходить в совершенно разные части кадра.

Для снижения нагрузки на память:

- вход для `SAM` уменьшается по разрешению,
- запрашивается только одна маска,
- после обработки очищается кэш и выгружается модель.

## Используемые индексы растительности

В модуле вычисляется несколько RGB-индексов и вспомогательных признаков:

- `ExG` (Excess Green),
- `ExGR`,
- `NDI`,
- `VARI`,
- `GLI`,
- `CIVE`,
- green ratio,
- hue score,
- насыщенность,
- склонность к зелёному в пространстве `Lab`.

Эти признаки не используются по отдельности как финальный результат. Они объединяются в карту поддержки растительности, которая затем участвует в построении маски и карт.

## Какие карты строит модуль

Модуль сохраняет и отображает несколько видов карт.

### Карта растительности

Показывает, где на изображении вероятнее всего находится растительность и насколько сильна поддержка гипотезы “это растительность”.

Эта карта строится по vegetation score и локальной плотности.

Она отвечает на вопросы:

- где расположена растительность,
- где она выражена сильнее,
- где сигнал слабый.

### Сводная тепловая карта

Это объединённая визуализация для быстрого просмотра результата.

Она смешивает карту поддержки растительности, локальную плотность и нормализованную информацию о локальном `LAI`. Это удобная операторская карта, но она не является строгим полем локального `LAI`.

### Карта распределения LAI

Это основная аналитическая карта модуля.

Она показывает локальное распределение `LAI`, рассчитанное из локальной плотности и локальной доли просветов. То есть это локальное поле `LAI`, полученное по той же физической логике, что и глобальная оценка.

Эта карта отвечает на вопросы:

- где покров плотнее,
- где локальный `LAI` ниже,
- как `LAI` распределён внутри одного изображения.

## Какие метрики сохраняются в Odoo

Для каждого расчёта модуль сохраняет:

- исходное изображение,
- средний `LAI`,
- карту растительности,
- сводную тепловую карту,
- карту распределения `LAI`,
- оценку уверенности,
- процент покрытия растительностью,
- зелёную долю,
- долю просветов,
- эффективный коэффициент `k`,
- однородность текстуры,
- стандартное отклонение локального `LAI`,
- локальные перцентили `LAI P10` и `LAI P90`,
- класс освещения,
- версию метода,
- текст рекомендации,
- при наличии — дополнительную AI-оценку сцены.

## Оценка уверенности результата

Уверенность не “угадывается” по самому значению `LAI`.

Она оценивается по качеству входного изображения и устойчивости сегментации:

- уровень размытия,
- качество экспозиции,
- согласованность бинарного и мягкого покрытия,
- рабочий диапазон покрытия,
- стабильность текстуры.

Это помогает понять, насколько результат можно использовать для практического сравнения.

## Поддерживаемые типы сцен

В модуле предусмотрены следующие режимы сцены:

- `wheat`
- `corn`
- `sunflower`
- `soy`
- `mixed`
- `vertical`

Эти режимы влияют на ожидаемое поведение покрова и на параметры расчёта `k_eff`.

Например:

- `vertical` подходит для фасадов, стен, шпалер и вертикального озеленения,
- `mixed` — самый безопасный универсальный режим, если сцена заранее не стандартизирована.

## Пользовательская калибровка

Пользователь может включить ручную калибровку и задать:

- центр зелёного оттенка,
- ширину или чувствительность оттенка,
- минимальный `LAI`,
- максимальный `LAI`.

Это полезно для локальных экспериментов и адаптации к конкретному способу съёмки, но для повседневной работы безопаснее использовать значения по умолчанию.

## Дополнительная CLIP-оценка сцены

В модуле есть необязательный шаг интерпретации сцены на базе CLIP.

Эта часть не участвует в самом расчёте `LAI`. Она служит только как дополнительный описательный слой и может классифицировать сцену, например, как:

- здоровая плотная растительность,
- стрессовая или пожелтевшая растительность,
- засорённая сцена,
- редкий покров или почти голая почва.

Функция управляется через настройки окружения и может быть выключена без влияния на расчёт `LAI`.

## Производительность и память

Модуль рассчитан на работу внутри Odoo-сервера, поэтому поведение по памяти критично.

Для этого в модуле используются:

- уменьшение изображения,
- ограничение рабочего разрешения,
- очистка промежуточных массивов,
- хранение карт в JPEG,
- уменьшенное разрешение для `SAM`,
- явная очистка кэша `SAM` после запроса.

Даже с этими мерами `SAM` остаётся заметно тяжелее, чем `cv_ensemble`.

Для рабочей эксплуатации рекомендуется:

- использовать `cv_ensemble` как основной режим,
- включать `sam` только при необходимости,
- следить за памятью Odoo, если включены тяжёлые модели.

## Почему два метода могут немного отличаться

Два режима сегментации всё равно могут строить немного разные карты.

Это нормально, потому что:

- `cv_ensemble` — детерминированный RGB-конвейер,
- `sam` — модель уточнения маски по prompt.

Но после выравнивания логики оба метода должны быть близки друг к другу, потому что опираются на один и тот же vegetation prior. Если различия слишком большие, это обычно связано с одной из причин:

- сложное освещение,
- жёсткие тени,
- слабый зелёный сигнал,
- сложный фон,
- размытие,
- нетипичная окраска растений,
- нехватка памяти при работе тяжёлой модели.

## Ограничения метода

У модуля есть важные ограничения.

### Физические ограничения

Одно RGB-изображение не может восстановить истинный биофизический `LAI` с той же надёжностью, как специализированные приборы или разрушительные измерения.

Результат нужно интерпретировать как:

- косвенную оценку,
- практический скрининговый показатель,
- относительную метрику для сравнения по времени или между участками.

### Ограничения по изображению

Качество результата может ухудшаться, если снимок содержит:

- жёсткие тени,
- пересветы,
- сильное размытие,
- большой наклон камеры,
- много фона,
- неоднородное освещение,
- нетипичные цвета листвы.

### Насыщение на плотном покрове

Очень плотный покров может “сжимать” информацию о видимых просветах. В этом случае чувствительность метода падает, а высокий `LAI` может недооцениваться.

## Рекомендации по съёмке

Чтобы повысить качество результата:

- снимайте как можно более перпендикулярно покрову,
- по возможности избегайте жёстких теней,
- избегайте пересветов,
- старайтесь, чтобы растительность занимала существенную часть кадра,
- при мониторинге по датам держите похожее кадрирование,
- используйте сходные условия съёмки для повторных наблюдений.

## Работа через веб-интерфейс

Веб-часть модуля предоставляет:

- форму загрузки,
- выбор культуры или сцены,
- выбор режима сегментации,
- блок пользовательской калибровки,
- предпросмотр изображения,
- страницу результата с картами и метриками,
- ссылку на скачивание карты `LAI`.

Интерфейс сделан простым, чтобы расчёт можно было запускать без отдельной технической подготовки.

## Модель данных

Основная модель Odoo:

```text
lai.calculation
```

Она хранит:

- загруженное изображение,
- рассчитанный `LAI` и связанные метрики,
- построенные карты,
- метаданные, такие как тип сцены и выбранный метод,
- пользователя и дату расчёта.

## Основные файлы модуля

Ключевые файлы:

- `models/lai_calculation.py`
  Основная Odoo-модель и верхнеуровневый конвейер обработки.

- `models/cv_engine.py`
  Научная RGB-логика, индексы растительности, поддержка сегментации, формула `LAI`, карты плотности и локального `LAI`.

- `models/sam_adapter.py`
  Экспериментальный путь сегментации на базе `SAM` с привязкой к RGB prior.

- `models/clip_adapter.py`
  Необязательная интерпретация сцены на базе CLIP.

- `controllers/main.py`
  Веб-контроллер для загрузки, валидации, обработки и вывода результата.

- `views/templates.xml`
  Шаблоны веб-страниц калькулятора и результата.

- `static/src/js/lai_calculator.js`
  Поведение фронтенда: предпросмотр, валидация, переключатели интерфейса.

## Установка

Поместите модуль в каталог `addons` Odoo и обновите список приложений стандартным способом.

Для работы модуля ожидаются Python-зависимости для включённых функций.

Базовые зависимости:

- `numpy`
- `opencv-python`
- `Pillow`

Необязательные или экспериментальные зависимости:

- `torch`
- `torchvision`
- `segment-anything`
- `transformers`

Если зависимости для `SAM` или `CLIP` отсутствуют, основной RGB-путь всё равно может использоваться.

## Рекомендуемая конфигурация для продакшена

Для стабильной рабочей эксплуатации рекомендуется:

- использовать `cv_ensemble` как режим по умолчанию,
- держать `sam` как экспериментальный или резервный режим,
- следить за памятью Odoo при включённых тяжёлых моделях,
- валидировать результат на собственной схеме съёмки,
- использовать повторные снимки в близких условиях, если задача связана с мониторингом.

## Краткий вывод

`lai_estimator` — это практический модуль Odoo для косвенной оценки `LAI` по RGB-фотографии.

Он построен вокруг:

- объяснимого RGB-анализа растительности,
- инверсии по Beer-Lambert,
- построения локальных карт `LAI`,
- простого веб-интерфейса,
- опциональных AI-компонентов для сегментации и описания сцены.

Наибольшую пользу модуль даёт как инструмент повторяемого мониторинга и сравнительной оценки состояния растительности, а не как абсолютная замена специализированных научных методов измерения.
